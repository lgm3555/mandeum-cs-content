## 질문
브라우저에서 도메인 이름에 해당하는 IP 주소를 찾을 때 DNS는 어떤 역할을 하며, 매번 루트 서버까지 조회하나요?

## 정답
DNS는 도메인 이름에 연결된 레코드를 찾는 시스템입니다. IP 주소 조회에는 보통 A 또는 AAAA 레코드를 사용합니다. 캐시가 유효하면 저장된 결과를 사용할 수 있어, 매번 루트·최상위 도메인·권한 서버를 모두 방문하지는 않습니다.

## 해설
### 캐시가 없다고 가정하면

단순화한 예시에서 기기는 재귀 리졸버에 `www.example.com`의 주소를 요청합니다. 리졸버는 필요한 캐시가 없다면 루트에서 `.com` 담당 서버를 안내받고, 그 서버에서 `example.com`의 권한 서버를 안내받은 뒤, 권한 서버에 해당 이름의 레코드를 묻습니다. 브라우저가 모든 서버에 직접 묻는 흐름은 아닙니다.

![재귀 리졸버를 주소 안내원에 비유하고 루트, com, 권한 DNS에 순서대로 물어 IP 주소를 사용자에게 전하는 그림](../images/dns-resolution.png)

주소 안내원이 재귀 리졸버 역할을 합니다. 사용자는 안내원에게 요청하고, 안내원이 필요한 서버를 차례로 확인한 뒤 결과를 알려줍니다. 캐시와 별칭을 생략한 단순화이며, 실제 경로는 캐시된 정보와 응답 종류에 따라 달라집니다.

### TTL은 캐시를 사용할 수 있는 시간

레코드의 TTL은 해당 응답을 캐시에 얼마나 오래 보관할 수 있는지를 나타냅니다. 주소를 바꿔도 기존 캐시가 유효한 동안에는 일부 사용자가 이전 주소를 사용할 수 있습니다. 따라서 DNS 변경이 모든 사용자에게 동시에 보이는 것은 아닙니다.

### 이름 하나가 주소 하나는 아니에요

한 이름에 여러 주소가 연결될 수 있고, 메일 서버처럼 IP 주소 이외의 정보를 나타내는 레코드도 있습니다. DNS를 웹사이트 주소를 한 개의 IP로 바꾸는 기능으로만 이해하면 범위가 너무 좁아집니다.
